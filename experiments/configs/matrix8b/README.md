> `cot_strong`=sonnet, `probe_ood`, `probe_iid`=`sycophancy_cot`; no output judges, no control). The
> headline experiment is now the **MBPP-Honeypot reward-hacking matrix** —

The headline artifact (#25): **D[i][j] = how much training AGAINST detector i degrades held-out
detector j.** One run per row, all identical except which detector is `train_against`. Generated by
`experiments/make_matrix_configs.py` (don't hand-edit — regenerate so the rows stay coherent).

Policy = `Qwen/Qwen3-8B`. Probes MUST match the policy base model (off-model probing is unreliable,
`docs/MONITORS.md`) — this is why the matrix is 8B, not 4B: our strong detector (`diverse_deception`)
is 8B, and `train_against_cot.json` is already 8B. The old 4B probes (`Qwen3.5-4B/{doluschat,
sycophancy_cot}`) don't compose with an 8B policy.

## Pre-req: train the 8B iid sycophancy probe

`probe_iid` points at `data/probes/Qwen3-8B/sycophancy_cot`, which doesn't exist (only a 4B one does).
Two options:
- **Full 4-method matrix** — train it first (GPU, or local answer-only on short text). We established
  the iid probe is effectively answer-only anyway (the CoT-stripping bug + "no-CoT generalizes"), so
  it can be trained on CoT-stripped (short) sequences cheaply; the 4000-token-CoT read is the GPU-bound
  part (#32) and isn't needed.
- **Runnable-today 3-method matrix** — drop it: `make_matrix_configs.py --skip probe_iid`. This still
  shows the cross-method (CoT-vs-probe) decorrelation headline; add the iid column later.

## Run it (GPU/tinker)

```bash
uv run python experiments/make_matrix_configs.py           # (re)generate row_*.json
# one run per row:
for c in experiments/configs/matrix8b/row_*.json; do
  uv run python experiments/run_experiment.py --config "$c"
done
# assemble the matrix from the per-run held-out eval curves (eval_metrics.jsonl):
uv run python -c "from monitordecorrelation.eval.degradation import build_degradation_matrix as b; \
  import glob; b(sorted(glob.glob('data/runs/matrix8b_*')), out_dir='data/runs/matrix8b')"
```

Outputs `data/runs/matrix8b/degradation_matrix.{json,csv,png}`. Each run already scores **all** monitors
(train-against + held-out) into `eval_metrics.jsonl` every `eval_every` steps, so the matrix needs no
post-hoc probe pass.

## Notes

- `max_tokens=4096` (not the smoke 1024): probes were fit on FINISHED rollouts, and scoring/penalizing
  truncated, unparseable text is junk. One value across all rows keeps the matrix coherent.
- Always read `behavior_rate` alongside the AUROCs — the key signature is behavior dipping then climbing
  as the policy learns to *hide* rather than *stop* (CLAUDE.md / EXPERIMENT_PLAN).
- Blocked on Aether's runpod/vastai org (no rented GPU yet). The 8B policy is a tinker run, but the
